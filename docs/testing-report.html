Lógica pura extraída de cada sensor

Cada sensor mezclaba matemática pura con llamadas a hardware (I2C, WiFi, FreeRTOS). Se extrajo la parte pura a módulos *Logic sin ninguna dependencia de ESP-IDF, testeables en segundos sobre cualquier máquina.

SensorCurrentTimeLogic testeado

Riego

croniot-watering-system

La pieza más crítica: bomba y válvulas

TaskWaterPlants mezclaba la secuencia de apertura/riego/cierre directamente con llamadas a GPIO — imposible de testear sin hardware real. Se introdujo una interfaz de driver para poder simular la bomba y las válvulas.

IWaterGpioDriver + WaterSequenceController testeado

La secuencia abrir→regar→parar→cerrar ahora se verifica pin por pin con un driver simulado, sin tocar hardware.

Validación de duración corregido

El rango 1-600s solo existía como metadato — nunca se aplicaba. Ahora se recorta (clampDurationSeconds) antes de mover la bomba.

Riesgo bomba compartida documentado

TaskWaterPumpSwitch puede encender la bomba sin abrir ninguna válvula, sin que TaskWaterPlants se entere. Test explícito que deja el riesgo visible — no se resuelve aquí.

BLE & mensajería

croniot-iot

El SDK: passkey BLE y ruteo de mensajes

El punto de mockeo más limpio del SDK es CommChannel. Se construyó un canal falso para verificar cómo MessageBus reparte los mensajes entre canales, y se aisló la validación del passkey BLE del stack de NimBLE.

BleChannelLogic testeado

Validación del passkey de 6 dígitos (corto, largo, no numérico, ceros a la izquierda, vacío) sin arrancar NimBLE.

FakeCommChannel + MessageBus testeado

Confirma que login/registro van solo al canal con auth, que los datos se difunden a todos los canales, y el modo "solo BLE" que usa esta misma rama.

Validación real, no solo en host

Dos bugs que el build en host nunca hubiera visto

Además de los 82 tests, se corrió idf.py build contra el target real (esp32-c6) usando el ESP-IDF 5.4.1 instalado localmente. Eso reveló dos errores introducidos por el propio refactor:

Excepciones de C++ deshabilitadas en este build

atrapado y corregido

El primer intento de parseDurationSeconds usaba try/catch. Este proyecto compila con CONFIG_COMPILER_CXX_EXCEPTIONS=n — ni siquiera compilaba. Se reescribió con std::from_chars, sin excepciones, preservando el mismo comportamiento (incluida la rareza de que "30abc" parsea como 30).

Definición huérfana en SensorBattery.cpp

atrapado y corregido

Al mover voltsToPercentage a SensorBatteryLogic quedó la implementación vieja suelta en el .cpp, sin declaración en el header. El compilador real lo marcó de inmediato; los tests en host nunca lo hubieran notado porque no compilan ese archivo.

Reportado, no corregido

Hallazgos que quedan fuera de este trabajo

Por decisión tuya durante la sesión, estos quedan documentados pero intactos:

BLE sin autenticación real

reportado

main.cpp fija ble.password pero nunca ble.securityEnabled = true — el pairing nunca se activa pese a haber contraseña configurada. Falla en modo abierto, no cerrado.

sdkconfig versionado con Bluetooth apagado

reportado

Un idf.py build limpio en esta rama fallaría igual: CONFIG_BT_ENABLED no está activo en el sdkconfig commiteado, justo en la rama que depende de BLE.

Integración continua

Tres workflows, dos repos

GitHub Actions en ambos repositorios. El compile-gate real corre en un contenedor espressif/idf:v5.4.1 y hace checkout de croniot-iot como directorio hermano, pineado por SHA en .ci/croniot-iot-ref.txt para que un cambio ajeno en el SDK no rompa el CI de este repo en silencio.

host-tests ambos repos

Compila y corre los 82 tests con ctest. Sin toolchain ESP-IDF — el job más rápido, primero en reportar en cada PR.

compile-esp32c6 watering-system

Build real de firmware para el target esp32-c6. El mismo comando validado localmente en esta sesión.

static-analysis ambos repos

cppcheck, no bloqueante todavía — se espera ruido contra el código legacy no tocado hasta ajustar supresiones.

cd components/croniot/test_host cmake -S . -B build cmake --build build -j ctest --test-dir build --output-on-failure

source $IDF_PATH/export.sh idf.py build
